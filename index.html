How the scan works, limitations, and secure deployment

Searches accessible ArcGIS portal items, then reads JSON definitions for web maps, web scenes, applications, dashboards and other JSON-backed items. It detects references by 32-character ArcGIS item IDs and matches service URLs to loaded layers. Counts are calculated only across the loaded inventory. A partial scan can undercount. REST access permissions limit results; organisation searches are not equivalent to all content unless your role permits access. Some app configurations, external REST URLs, FME integrations, embedded content and runtime-generated references cannot be fully detected. Direct links and transitive downstream links are shown separately; loops are handled.

For live use, host the HTML at an HTTPS URL and register the URL in an ArcGIS OAuth application. The application uses the ArcGIS Maps SDK IdentityManager (OAuth 2.0 with PKCE) and fetches JSON through the portal sharing REST API; no service editing operations are called. Client ID is not secret; do not embed client secrets. Only use on a trusted host. Browser privacy extensions, cross-origin policies, or organisation security policies may affect sign-in or certain item reads. CSV/JSON downloads and imports remain local to your browser.

For large organisations, the search API is capped at 10,000 items per search. Split very large inventories by owner/date or run a backend Python audit. This standalone viewer limits live downloads to 10,000 and concurrent definition reads to four. Review no-reference candidates manually before archiving.
